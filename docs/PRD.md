## 1. 项目概述

### 1.1 背景与痛点

旅行前规划与旅行中执行普遍面临以下问题:
1. **信息碎片化** —— 景点、路线、酒店、账目散落在小红书、公众号、备忘录、Excel,难以集中管理。
2. **行程安排不合理** —— 手动拼排,经常出现「点密集但通勤被忽略」「赶路 2 小时看景 30 分钟」。
3. **行中记账繁琐** —— 旅途结束算账对不上,分摊困难。
4. **行中无网即废** —— 依赖在线地图,信号差时已规划行程无法查看。

### 1.2 解决方案

- **地图可视化 + 结构化时间轴**:以"天"为单位,把景点、通勤、酒店串成一条时间轴。
- **一站式地图编辑**:左侧天卡片列表,右侧全屏高德暗色地图;点击某天展开景点/酒店/交通三种类型的搜索添加面板,搜索结果实时在地图上定位预览。
- **智能路径计算**:依据出行方式自动算通勤,一键顺路重排。
- **AI 景点卡片 + 自建攻略库**:LLM 按需生成「推荐原因 / 避坑指南 / 建议时长」结构化卡片并缓存。
- **本地优先存储**:核心数据本地 IndexedDB(Dexie.js)存储,行中断网可用。

### 1.3 目标(非目标)

| 目标 | 非目标 |
| :--- | :--- |
| 单人/小团(2-6人)行程规划 | 商业旅行平台、预订支付 |
| 城市级多日(2-15天)行程 | 抢票、实时比价、团队协作编辑 |
| 行中查看已规划行程 + 记账 | 社交分享裂变、UGC 社区 |
| AI 辅助生成景点卡片 | AI 全自动生成完整行程 |
| V1 一期范围(见 §8) | 数据导出/防抖/行程复用(见 §9 V2 池) |

## 2. 核心功能需求

### 2.1 行程创建流(三步向导化) — V6.0 新增

> 取消单一表单创建,改为 **「城市/晚数/模板」三步创建向导**。冷启动关键:通过模板库匹配经典行程,一键套用生成完整数据。

```
【第一步：确定目的地与天数】
 1. 输入/选择目的地(支持多城市,如:西宁、张掖、敦煌)
 2. 录入起止日期(自动计算总天数,如 7 天)
                    │
                    ▼
【第二步：分配城际晚数(Night Allocation)】
 3. 系统提供城市列表,用户调整在每个城市的住宿晚数:
    ├─ 西宁：[ 2 ] 晚
    ├─ 张掖：[ 1 ] 晚
    └─ 敦煌：[ 3 ] 晚 (总晚数必须等于总天数 - 1)
                    │
                    ▼
【第三步：智能模板匹配(冷启动关键)】
 4. 系统检索本地 seed 库中包含这三个城市的经典行程(如:青甘大环线经典7日游)
 5. 用户选择:
    ├─ 方案甲：经典紧凑线 [预览] ──▶ 一键套用 ──▶ 生成完整的行程数据
    └─ 方案乙：空白行程 ───────────▶ 生成只有每日酒店骨架的空白行程
```

**校验规则**:
- 第二步总晚数 ≠ 总天数-1 → 提示并阻止进入下一步
- 城市列表至少 1 个;日期 end ≥ start
- 模板匹配:按 `trip_templates.cities` 与用户城市列表的重合度排序,重合度最高优先

### 2.2a 地图行程顺序标注(V6.2)

**问题**:当前地图 Marker 只显示 `daySeq`(一堆"1"),同一天内景点先后无法分辨。

**方案**:
- Marker 内容改为 **`D日-序号`**(如 `1-1`、`1-2`、`1-3`),同一天同色、序号随 orderSeq 递增
- 同一天相邻景点画**带箭头 Polyline**(`showDir: true`),箭头指向下一站,直观看出"先去哪再去哪"
- 不同天不同颜色区分,天与天之间用虚线连接
- 预览模式同步:宏观轨迹虚线加箭头 + 每天大纲带编号

### 2.2b 每日行程总时长 + 交通方式可选(V6.2)

**问题**:`calcDayTiming` 固定用 40km/h 直线估算,不看交通方式;`transportMode` 只有 walk/drive/transit。

**方案**:
- **扩展交通方式**:`walk | drive | transit | train | flight`(新增城际火车/飞机)
- 相邻两点间**用户可选交通方式**,交互:下拉/单选 —— 🚶步行 / 🚗打车 / 🚌公交 / 🚄火车 / ✈️飞机
- **时间计算**:
  | 交通方式 | 适用范围 | 时长来源 |
  | :--- | :--- | :--- |
  | 步行/打车/公交 | 城内 | 高德 JS API `getDuration`(走 route_cache 防重复计费) |
  | 火车 | 城际 | 直线距离 ÷ 250km/h 粗估 |
  | 飞机 | 城际 | 直线距离 ÷ 800km/h 粗估 |
- **每日总时长** = Σ景区游览时长 + Σ相邻点通勤时长
  - 明细顶部显示:`单日总时长 ≈ 路上 Xh + 游览 Xm`
  - 时间轴按时间段(上午/中午/下午/晚上)细化
- 示例:
  ```
  Day 2 · 西宁
  09:00 出发(酒店)
  09:30-11:30 塔尔寺(游览2h)           🚗打车 20min
  11:50-12:30 莫家街(午餐40min)        🚶步行 15min
  12:45-14:45 青海湖(游览2h)          🚄火车 2h(城际)
  ```

### 2.3 目的地与景点检索(POI 管理)

#### 2.3.1 城市/目的地检索
- **数据来源**:**高德 Map**(地理编码 + POI 检索)
- **调用方式**:JS API 内置 `PlaceSearch`(无需 Web 服务 Key)
- **验收要点**:输入"塔尔寺"能命中城市并可下钻区县

#### 2.3.2 地图模式与 POI 展示
- **功能描述**:加载目的地地图,以 Marker 标注景点、餐厅、酒店
- **交互逻辑**:点击 Marker 弹气泡,显示名称、推荐度、简要介绍
- **验收要点**:Marker 可点击;气泡内容断网时可用(读本地 POI 缓存)

#### 2.3.3 景点添加至行程
- **功能描述**:景点详情页/气泡内提供「添加至行程」
- **交互逻辑**:两个去向 —— 加入「暂存箱」或直接安排到具体某天
- **验收要点**:同日重复添加须提示;暂存箱支持批量拖入某日

#### 2.3.4 推荐点评与时长来源(5 层读取链)
- **来源读取链(按优先级,前层未命中自动降级到下一层,全链可被用户手动值覆盖):**
  1. **个人攻略库(RAG,可选软依赖)** —— Supabase pgvector,配置缺失或知识库为空时静默跳过
  2. **AI 卡片缓存**(`poi_ai_cards` 永久缓存)
  3. **LLM 生成**(TokenHub deepseek-v4-flash,生成后写入缓存)
  4. **类型兜底值**(景点90/餐厅60/购物45/未知90)
  5. **用户手动改**(改后锁定,不被上述层覆盖)
- **验收要点**:同一景点二次查询不产生 API 调用;断网可读已缓存卡片;RAG 为空时整体流程不受影响

### 2.4 行程骨架(交通与酒店)

#### 2.4.1 大交通记录(往返/城市间)
- **功能描述**:记录出发地、目的地、交通工具(飞机/高铁/自驾)、起抵时间、班次/车次
- **Day 边界推导(显式优先级表)**
  > 某 Day 的 `start_time` 取以下顺序的第一个可用值:
  > 1. 用户手动覆盖(已排点后锁定);
  > 2. 当日酒店 `check_in`(若当日入住);
  > 3. 前一日大交通 `arrive_at` **的次日 09:00**(跨夜到达时取到达日当天);
  > 4. 默认 09:00。
  > `end_time` 同理取:手动覆盖 → 当日酒店 `check_out` → 当日大交通 `depart_at` → 默认 20:00。

#### 2.4.2 酒店/住宿管理
- **功能描述**:记录名称、地址(地图打点)、入住日期、退房日期
- **同日双酒店(城市间切换日)规则:**
  > 当日既有 `check_out` 又有 `check_in` 时:起点 = 旧酒店,终点 = 新酒店;自动插入迁移缓冲项

### 2.5 路径规划与时间预估(行程填充)

#### 2.5.1 行动方式选择
- **功能描述**:相邻两点间可选:公共交通(地铁/公交)、自驾/打车、步行
- **默认**:步行;支持「今日全改为打车」批量操作

#### 2.5.2 时间与路程自动计算
- **计算公式**:
  ```
  下一景点到达时间 = 上一景点离开时间 + 路程通勤时间
  上一景点离开时间 = 到达时间 + 游览时间
  ```
- **缓存**:路径结果按 `md5(origin+dest+mode)` 入 `route_cache`(TTL 30 天)

#### 2.5.3 游览时间占位与空态
- **默认值体系**:AI 卡片 `suggest_duration` → 类型兜底 → 用户手动锁定
- **空态**:某 Day 未排任何点时,显示「今天还没有安排,去暂存箱换个景点进来」

### 2.6 智能行程优化

#### 2.6.1 单日顺路优化(一键重排)
- **算法逻辑**:取当天景点坐标 → 求通勤最短环线 → n≤8 Held-Karp / n>8 2-opt → 预览节省 → 确认回写
- 触发条件:当天 ≥2 个带坐标景点
- 展示单日行程时长统计(路上时长 + 游览时长)

#### 2.6.2 全局顺路优化(酒店锚点,V6.1)
**核心思路**:以酒店为固定锚点,景点按「离它最近的酒店」归位——**酒店住宿不受优化影响**,线路自然围绕每天住宿城市展开,不会出现 Day1→Day2→Day3 又折返回 Day1 附近的情况。

**三步流程**:
```
① 起点终点选择:起点=第一晚酒店,终点=最后一晚酒店(下拉可选其他天酒店)
      │
② 计算预览(不写库):
      │   · 从起点酒店 → 所有景点 → 终点酒店,求最短开放路径
      │   · 每个景点归属到「距离最近的酒店」所在天
      │   · 展示:节省分钟 + 优化后路线(按天)+ 移动清单(景点 DayX → DayY)
      ▼
③ 用户操作三选一:
      ├─ 取消          → 关闭预览,不改数据
      ├─ 确认保存      → 按移动清单把景点移到目标天,酒店不动;各天内部再顺路优化
      └─ 复制到新行程  → 生成一个全新的「优化版」旅程副本,当前行程不变
```

**约束**:
- 起点/终点必选酒店(需 ≥2 天带坐标酒店),酒店是固定锚点不参与重排
- 景点移动依据「最近酒店距离」,不会挪到没住那城市的日期
- 中间点走最短开放路径(从起点酒店到终点酒店),n≤9 Held-Karp / n>9 2-opt

#### 2.6.3 冲突预警
- **触发条件**:
  | 规则 | 判定 | 级别 |
  | :--- | :--- | :--- |
  | 时间重叠 | `前节点 leave_time > 后节点 arrive_time` | 黄 |
  | 闭馆冲突 | 当日 ∈ `poi.closed_days` | 黄 |
  | 通勤过紧 | `留白 < 通勤实际值 + BUFFER_MIN` | 黄 |
  | 预算超额 | `sum(expenses) > total_budget` | 红 |
  | 游览超建议 | 手动耗时 > `suggest_duration × 1.5` | 灰 |
  > `BUFFER_MIN = 15`(分钟)

### 2.7 记账与财务管理

#### 2.7.1 消费记录
- **分类维度**:大交通 / 住宿 / 餐饮 / 门票 / 本地交通 / 其他
- **输入校验**:金额 > 0 且 ≤ 999,999,最多两位小数;分类必选
- **离线**:记账支持离线录入,联网后增量上行(带 `dirty` 标记)

#### 2.7.2 预算与人数分摊
- **功能描述**:设总预算 → 实时显示「已花 / 剩余」;人均口径:默认「人均已花」
- **刷新时机**:任何消费增/删/改后**实时重算**

## 5. 接口与算法

### 5.1 外部依赖

| 依赖 | 用途 | 调用方式与约束 |
| :--- | :--- | :--- |
| 高德 JS API | 地图渲染、POI 搜索(PlaceSearch)、路径规划(Driving/Walking/Transfer) | JS Key + 安全密钥;**搜索走 JS API PlaceSearch,无需 Web 服务 Key** |
| LLM(TokenHub) | AI 景点卡片 | `https://tokenhub.tencentmaas.com/plan/v3`, Bearer Token;结果落 `poi_ai_cards` |
| (可选)RAG | 个人攻略库检索 | Supabase pgvector,配置缺失/为空**静默跳过** |
| (可选)Supabase | 云同步 | 本地为主,同步为从 |

### 5.2 核心算法:一键顺路优化
1. 输入:当天酒店坐标 `H` + 景点坐标集 `P = {p1..pn}`
2. 构建耗时矩阵 `D[(i,j)] = route_cache(优先) 或 路径 API`
3. 求最短环线:n ≤ 8 Held-Karp;n > 8 2-opt
4. 输出新 `order_seq` + 节省分钟预览
5. 确认后回写;撤销遵循单层快照规则

### 5.3 时间级联(纯函数)
```ts
cascadeTimes(start, [
  { visitMinutes, nextDurationMin }, ...
]) // → [{arrive, leave}...]
```
支持跨午夜 24h+ 记号(如 `25:30`)。

## 6. 非功能性需求

### 6.1 性能指标
| 指标 | 目标 |
| :--- | :--- |
| 时间轴渲染 | 单日 20 节点首屏 < 500ms |
| 地图加载 | 首帧 < 3s(弱网缓存瓦片) |
| 本地读写 | IndexedDB 查询 < 20ms |
| AI 卡片生成 | 单张 < 10s;本地命中 0 API 调用 |

### 6.2 缓存与配额策略
- POI 检索:JS API PlaceSearch 自带缓存,前端不复做
- 路径缓存:`route_cache` TTL 30 天
- AI 卡片:永久缓存

### 6.3 离线可用性
- 行程(trips+days+items+hotels+transports)全量本地 IndexedDB 存储
- 离线只读视图:时间轴、静态地图快照、景点卡片
- 弱网提示条「当前为离线/弱网模式,已展示缓存数据」

### 6.4 安全与隐私
- 数据纯私人,不出设备(RAG 检索与 LLM 生成除外)
- LLM/地图 Key 入 `.env` 并 gitignore
- 同步需显式开关
